# Basic Kotlin Syntax into Java Converter

# About

The program translates the basic Kotlin Syntax into a Java code. Kotlin.g4 is a grammar written using antl4 that accepts a code written in Kotlin, while [Kotlin2Java.java](http://kotlin2java.java) converts the code using rules specified.

String templates are supported: `"sum of $a and $b is ${a + b}"` becomes
`"sum of " + a + " and " + b + " is " + (a + b)`.

# How to build

Requires a JDK (17+) and the ANTLR 4 complete jar:

```
sudo apt-get install -y openjdk-17-jdk-headless
curl -LO https://www.antlr.org/download/antlr-4.13.2-complete.jar   # or into /usr/local/lib
```

`env.sh` finds them, it installs nothing: the JDK from `JAVA_HOME` or the `PATH`,
the jar from `ANTLR_JAR`, from this directory (which pins a version), or else the
newest one found under `~/.local/lib`, `/usr/local/lib` and `/usr/share/java` -- so an
old copy in one place cannot shadow a newer one in another. `build.sh` prints which
JDK and jar it used.

```
./build.sh     # generates the parser into build/gen, compiles into build/classes
./tests.sh     # translates every input_files/*.kt and runs javac on each result
./run_tests.sh # runs every program tests.sh produced and prints its output
```

On Windows use `build.bat` instead of `build.sh`.

# How to run?

run the following command in your terminal

java Kotlin2Java [file].kt  #creates a default [input.java](http://input.java) file where the code is stored

java Kotlin2Java [file].kt [file].java  # creates a file with a specified name

java Kotlin2Java --classpath android.jar [file].kt [file].java  # see "Compiled libraries"

The input can also come from stdin or straight from the command line, in which
case the Java code is printed to stdout (as class `Main`) unless an output file
is given:

```
cat file.kt | java Kotlin2Java -
java Kotlin2Java - Out.java < file.kt
java Kotlin2Java -e 'fun main() { println("hi") }'
```

The generated file is always written as UTF-8, so compile it with that encoding:
`javac -encoding UTF-8 Out.java`. Left to its own default, javac reads the file in
the platform encoding, and a string with an accent in it comes out mangled without
any error -- on Windows `"café"` compiles to `"cafÃ©"`, four characters becoming
five. The scripts in this repository already pass the flag.

# Example

## Kotlin code

```kotlin
fun main() {
val rectangle = Rectangle(5.0, 2.0)
val triangle = Triangle(3.0, 4.0, 5.0)
println("Area of rectangle is ${rectangle.calculateArea()}, its perimeter is ${rectangle.perimeter}")
println("Area of triangle is ${triangle.calculateArea()}, its perimeter is ${triangle.perimeter}")
}
```

```kotlin
abstract class Shape(val sides: List<Double>) {
val perimeter: Double get() = sides.sum()
abstract fun calculateArea(): Double
}
```

```kotlin
interface RectangleProperties {
val isSquare: Boolean
}
```

```kotlin
class Rectangle(
var height: Double,
var length: Double
) : Shape(listOf(height, length, height, length)), RectangleProperties {
override val isSquare: Boolean get() = length == height
override fun calculateArea(): Double = height * length
}
```

```kotlin
class Triangle(
var sideA: Double,
var sideB: Double,
var sideC: Double
) : Shape(listOf(sideA, sideB, sideC)) {
override fun calculateArea(): Double {
val s = perimeter / 2
return Math.sqrt(s * (s - sideA) * (s - sideB) * (s - sideC))
}
}
```

# Translation

(this is the actual output of `java Kotlin2Java input_files/input36.kt output36.java`)

```java
// generated by Kotlin2Java from input36.kt
import java.util.*;

public class output36 {
    public static void main(String[] args) {
        final Rectangle rectangle = new Rectangle(5.0, 2.0);
        final Triangle triangle = new Triangle(3.0, 4.0, 5.0);
        System.out.println("Area of rectangle is " + (rectangle.calculateArea()) + ", its perimeter is " + (rectangle.getPerimeter()));
        System.out.println("Area of triangle is " + (triangle.calculateArea()) + ", its perimeter is " + (triangle.getPerimeter()));
    }

    static abstract class Shape {
        final List<Double> sides;

        public Shape(List<Double> sides) {
            this.sides = sides;
        }

        public double getPerimeter() {
            return sides.stream().mapToDouble(Double::doubleValue).sum();
        }

        public abstract double calculateArea();
    }

    interface RectangleProperties {
        boolean getIsSquare();
    }

    static class Rectangle extends Shape implements RectangleProperties {
        double height;
        double length;

        public Rectangle(double height, double length) {
            super(List.of(height, length, height, length));
            this.height = height;
            this.length = length;
        }

        @Override
        public boolean getIsSquare() {
            return length == height;
        }

        @Override
        public double calculateArea() {
            return height * length;
        }
    }

    static class Triangle extends Shape {
        double sideA;
        double sideB;
        double sideC;

        public Triangle(double sideA, double sideB, double sideC) {
            super(List.of(sideA, sideB, sideC));
            this.sideA = sideA;
            this.sideB = sideB;
            this.sideC = sideC;
        }

        @Override
        public double calculateArea() {
            final double s = getPerimeter() / 2;
            return Math.sqrt(s * (s - sideA) * (s - sideB) * (s - sideC));
        }
    }
}
```

# Dependencies

## Kotlin stdlib: mapped, not translated

The stdlib is not Kotlin source you can reach from your project, and its own code
uses far more of the language than this grammar covers. It is also unnecessary:
`kotlin.text.Regex` is a thin wrapper over `java.util.regex` (that is literally how
the stdlib implements it), and `kotlin.math` is a set of one-to-one aliases for
`java.lang.Math`. So both are rewritten directly, and the needed Java import is
added only when used.

| Kotlin | Java |
| --- | --- |
| `Regex(p)` / `p.toRegex()` | `Pattern.compile(p)` |
| `re.matches(s)` | `re.matcher(s).matches()` |
| `re.containsMatchIn(s)` | `re.matcher(s).find()` |
| `re.replace(s, r)` | `re.matcher(s).replaceAll(r)` |
| `re.split(s)` | `List.of(re.split(s))` |
| `re.find(s)` / `re.matchEntire(s)` | a generated `regexFind` / `regexMatchEntire` helper |
| `re.findAll(s)` | a generated `regexFindAll` helper, answering `List<String>` |
| `m.value` / `m.groupValues` | `m.get(0)` / `m` itself |
| `sqrt`, `abs`, `max`, `pow`, `ln`, ... | `Math.sqrt`, `Math.abs`, ..., `Math.log` |
| `PI`, `E` | `Math.PI`, `Math.E` |

A `MatchResult` is carried as its list of group values, index 0 being the whole
match, so `find(s)` answers a `List<String>?`: `.value` becomes `get(0)` and
`.groupValues` is the list itself. `findAll(s)` collapses Kotlin's lazy
`Sequence<MatchResult>` into a `List<String>` of the matched texts, which can be
iterated with `for`. A Regex method with no counterpart (`replaceFirst` with a
lambda, `escape`, ...) is reported as an error rather than guessed at.

## Your own code: resolved on disk

An import that is neither stdlib nor `java.*` is looked up as a file, using the path
the import states. Two roots are searched: the directory of the file being
translated, and the source root implied by its `package`, so `import demo.utils`
inside `src/demo/app.kt` finds `src/demo/utils.kt`. Both `.kt` and `.java` are
accepted, which means a dependency only has to be translated once.

A `.kt` dependency is parsed so that every reference can be qualified, and the
command to translate it is printed:

```
$ java Kotlin2Java app.kt App.java
note: dependency utils.kt is used; translate it with:  java Kotlin2Java utils.kt Utils.java   (or pass --deps)
```

With `--deps` it is translated and written alongside the output instead:

```
$ java Kotlin2Java --deps app.kt App.java
note: dependency utils.kt translated as Utils.java
note: wrote Utils.java
$ javac -encoding UTF-8 App.java Utils.java
```

Every generated file starts with `// generated by Kotlin2Java from <file>.kt`. The
name of a dependency's `.java` is chosen by this tool rather than by you, so that
line is also what it checks before writing one: a file of that name without the
mark was written by hand, and it is reported instead of being replaced.

Either way `twice(21)` from `utils.kt` becomes `Utils.twice(21)`, `VERSION` becomes
`Utils.VERSION` and a class `Counter` becomes `Utils.Counter`. The dependency's class
name is its file name capitalised (`utils.kt` -> `Utils`), which is why the printed
command already uses the right name.

A dependency that is already `.java` cannot be parsed by this grammar, so its
visible static declarations are read off the source to qualify references, and it
has to be compiled alongside the output.

## Compiled libraries: imported, with their types read

A library such as the JDK or the Android SDK is not translated at all: `android.*`
is Java already, and Java calls it as it is. What the translation does need is its
types. Kotlin infers `val d = LocalDate.now()`, Java has to write `LocalDate d`, and
that type is nowhere in the Kotlin source. So it is read off the compiled classes,
by reflection (they are loaded, never initialised: none of their code runs).

The JDK is always available. Anything else is given with `--classpath`, jars or
directories separated as the platform does it (`:`, or `;` on Windows):

```
java Kotlin2Java --classpath ~/Android/Sdk/platforms/android-34/android.jar Main.kt Main.java
```

An import that is not this project's source is kept when it names a class or a
package of the JDK or of the classpath; otherwise it is dropped with a warning, as
before. With the classes known:

| Kotlin | Java |
| --- | --- |
| `val d = LocalDate.now()` | `final LocalDate d = LocalDate.now();` |
| `d.year` / `view.isEnabled` | `d.getYear()` / `view.isEnabled()` |
| `view.text = "hi"` | `view.setText("hi");` |
| `view.text += "!"` | `view.setText(view.getText() + "!");` |
| `month.name` / `month.ordinal` (an enum) | `month.name()` / `month.ordinal()` |
| `Locale.LanguageRange.parse(s)` | the same, typed `List<java.util.Locale.LanguageRange>` |

Kotlin's own rules are followed: a public field wins over a getter of the same
name, `getURL()` is the property `url`, an `isX()` answering a boolean is the
property `isX`, and a method of the class wins over a Kotlin extension of the same
name. A type is written by its simple name only where that name is sure to mean it
in the generated file; otherwise it is qualified (a `class DayOfWeek` of the file
makes the library's `java.time.DayOfWeek`).

When a type cannot be known for certain, it is left unknown, which is what the
translator did before: overloads that fit the arguments and disagree on what they
return (an exact match of the argument types is taken first, as Java and Kotlin
do), a type variable (`Map<K, V>.get`), an array. Generic classes other than
`List<T>`/`Set<T>` are written raw. Two things are refused instead of being guessed:

- assigning a property that has a getter and no setter (Kotlin reads it as a
  `val`),
- `+=` and the like on such a property when the receiver is a call, since reading
  and writing back would run the call twice.

What this does not cover is everything around it: the grammar still rejects most of
a real Android `Activity` (annotations, `?:`, multi-line lambdas, objects), and the
Kotlin-specific shapes of a library compiled from Kotlin (`Foo.Companion`, extension
functions as `FooKt.bar(x)`, default arguments, `suspend`) are not mapped. A class
the JDK has, such as `java.util.List`, is always read from the JDK, even when the
classpath is an android.jar whose API level lacks part of it.

# Android

Short version: the Java this tool writes runs on Android, but the tool translates
Kotlin *logic*, not Android *apps*. Take the translated classes into an Android
project for calculations, validation, collections, regexes or plain classes; do not
expect it to translate an `Activity`.

What works:

- The generated Java needs Java 9 at the most (`List.of`), and nothing past it.
  Lambdas compile for any Android version; `List.of` exists on a device from
  Android 11 (API 30), and streams from Android 7 (API 24). For an older `minSdk`,
  check that your build desugars them (`coreLibraryDesugaring`); this has not been
  tested here.
- With `--classpath android.jar` the SDK's classes are imported and their types
  known, so `view.text = "hi"` becomes `view.setText("hi");` (see "Compiled
  libraries" above). android.jar comes with the SDK platform
  (`sdkmanager "platforms;android-34"`); Android Studio is not needed for it.

What does not, and why:

- **Most of a real Android source file is rejected by the grammar.** Annotations
  (`@Composable`, `@Override`...), `?:` and `!!`, `object` and `companion object`,
  `data class`, `try`/`catch`, lambdas of more than one expression, default and
  named arguments, extension functions and coroutines are all outside it (see
  "Limitations"). A typical `Activity`, `Fragment` or `ViewModel` uses several.
- **The output is a console program.** A file translates to a class whose entry
  point is `main`, and `println` becomes `System.out`. Android never calls `main`,
  and `System.out` goes to Logcat, not to the screen.
- **Libraries compiled from Kotlin are seen as plain Java.** Most of AndroidX and
  all of Jetpack Compose are Kotlin. Their companion objects (`Foo.Companion.bar()`),
  extension functions (`FooKt.bar(x)`), default arguments and `suspend` functions
  are not mapped, and Compose cannot be called from Java at all: it needs the
  Kotlin compiler plugin.
- **`java.*` is read from the JDK running the translator**, not from android.jar,
  so a JDK class or method missing at your `minSdk` (`java.time` before API 26
  without desugaring, say) is not reported.
- **Nothing of the Android build is produced**: no Gradle files, no manifest, no
  resources.

And the question of whether to do this at all: Android supports Kotlin directly,
and it is the language Google recommends for it. Translating to Java is only
needed when the code has to live in a Java-only project or toolchain.

# Editor support

`tools/notepad++/` has Kotlin and Gradle support for Notepad++ (syntax highlighting
and autocompletion), from [bsobol/npp-kotlin-gradle](https://github.com/bsobol/npp-kotlin-gradle)

- Highlighting: Language > Define your language... > Import, pick
  `userDefinedLang_Kotlin.xml` (or `_Darcula` for a dark theme), restart Notepad++.
- Autocompletion: copy `Kotlin.xml` into `C:\Program Files\Notepad++\autoCompletion\`
  (`plugins\APIs\` on versions before 7.6.3), restart Notepad++. With the Darcula
  definition, rename it `Kotlin_Darcula.xml` first.
- The Gradle files install the same way.

# Limitations

The grammar covers a subset of Kotlin. Anything outside it is rejected with a
syntax error and a non-zero exit code instead of silently producing wrong Java.

Supported: top-level functions and properties, classes (with or without a body)
using constructor properties, inheritance and interfaces, getters, abstract
members, interface methods and properties that carry an implementation (they
become Java `default` members), `override val` in a primary constructor,
local functions (including the variables they capture), `if`/`else if`,
`while`, `for` over ranges (`..`, `until`, `downTo`, `step`), `break`/`continue`,
nullable types (`String?`) on properties, parameters and locals, lists and `indices`,
`when` both as a statement and as a value (with block branches as a statement), a
getter body that is an `if` or a `when`, chained `else if` as a value,
`===` / `!==`, `+=` on a collection,
string templates, member chains such as
`a.b().c()`, assignment through a path (`car.engine.power = 1`), safe calls on a
named receiver, a class of the file used as a type, `listOf`/`setOf` and their
mutable counterparts, the `filter`/`map`/`sortedBy`/`forEach` pipeline and its
result (`val big = words.filter { it.length > 1 }`), `if`/`when`/a pipeline used as
a call argument, the
conversions `toInt`/`toDouble`/`toString`, and `kotlin.math` / `kotlin.text.Regex`.

Not supported:

- `Array`, `Char` and `Float` as declared types, generics beyond `List`/`Set`,
  data classes, objects.
- `try`/`catch`, the elvis operator `?:`, `!!`, classes nested inside a class,
  default and named arguments, extension functions, `companion object`,
  destructuring and coroutines. All of these are syntax errors, never silent.
- A local function that assigns to a variable it captures. Java cannot express
  that once the function is hoisted, so it is reported as an error; captures that
  are only read become extra parameters.
- A safe call on the result of a call (`f()?.g()`), and a range test on one
  (`f() in 1..3`), because the value would be evaluated twice. Assign it to a
  variable first.
- `x.indices` anywhere other than `for (i in x.indices)` and `i in x.indices`. It
  is a range, and Java has no value for one.
- Two files that import each other. Each generated class needs the other's
  declarations before its own are collected, so the cycle is reported instead of
  producing references that do not compile. Move what they share into a third file.
- A block branch in a `when` used as a value (`val x = when (n) { 1 -> { ... } }`).
  A Java conditional takes an expression, not statements; as a statement the block
  form is supported.
- A lambda body of more than one expression. The parameter may be `it` or named
  (`{ w -> w.length }`), and the body is that one expression.
- Stages other than `filter`/`map`/`sortedBy`/`forEach` in a pipeline (`any`,
  `count`, `reduce`).
- Names that Kotlin allows but Java reserves (`double`, `int`, `new`, ...). They are
  reported so they can be renamed in the Kotlin source.
- `==` between two operands whose types cannot be inferred falls back to Java's
  `==`. When the types are known it becomes `Objects.equals`, matching Kotlin's
  structural equality.
